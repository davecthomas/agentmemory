# v0.5: Decision Memory

Status: in progress (branch `feat/v0.5-decision-memory`)
Date: 2026-09-05
Replaces the per-turn capture pipeline described in `shared-repo-memory-system-design.md` and `gestalt-2-episode-graph-design.md`.

## Why rebuild

An audit of this repo's own memory on 2026-09-05 found:

| Signal | Value |
|---|---|
| Pending captures written | 129 |
| Background `claude -p` evaluations | hundreds (520 KB of LLM output in `enrichment.log`) |
| Checkpoints published, ever | 15 logged, 2 surviving on disk |
| Captures since 2026-04-20 | 0 (the hook was uninstalled on the author's machine) |
| Links in published memory that resolve | 18 of 35 |
| Python | 10,887 lines |

Root causes:

1. **Wrong capture unit.** A pending capture is `files touched` + `git diff --stat`. The *why* was in the conversation and was discarded at capture time for privacy. A subagent then spent a full session reconstructing intent from the diff.
2. **Wrong cadence.** Per-turn capture produced ~98% no-op evaluations. Git already logs activity; the two surviving events read like the PR descriptions for PR #10 and #12.
3. **Read model that fabricates.** The daily summary pasted one paragraph into *Top decision*, *Blockers*, *Why this mattered*, and *Decision candidates*. A fixed bug propagated into `catchup.md` as an **Active blocker** for every future session.
4. **Push-only.** Session start injected the index and three summaries. There was no way to ask "what do we know about `adapters/`?"
5. **No metric.** Nothing defined what "memory works" meant, so nothing could show it didn't.
6. **Drift.** ADR-0017 documents a six-item read path; `session-start.py` implemented two items. Two ADR formats coexisted, which truncated INDEX titles. "Immutable" events were deleted, leaving dangling links.

## Goal

A fresh agent session in a repo answers "why is X this way?" correctly from memory, without re-deriving it from code, and a teammate reviewing a PR sees the decisions it introduced.

Success is measured, not asserted: `evals/` scores a fresh `claude -p` session on repo questions with and without memory.

## What stays

- Memory is plain Markdown in Git under `.agents/memory/`. No service.
- ADRs are the only durable decision record. Promotion is explicit.
- Must-read ADRs plus the index are injected at session start and after compaction.
- Catch-up after `git pull` / checkout / rewrite.
- Nothing auto-commits or auto-pushes.

## What changes

| v0.4 | v0.5 |
|---|---|
| Per-turn pending capture + episode graph + background `claude -p` evaluation | **Decision notes**: the agent (or a human) appends a 3-line note when it makes a non-obvious choice. Zero LLM spawns. |
| `daily/YYYY-MM-DD/events/` + derived `summary.md` | `notes/YYYY-MM-DD.md`, append-only, committed with the code |
| Commit-time: nothing | `post-commit` hook appends a **candidate** note when a commit touches declared decision surfaces or its message carries a `Decision:` line. Deterministic; copies the commit body verbatim. |
| Session start injects INDEX + 3 summaries | Injects INDEX + must-read ADR *Decision* sections + recent notes + catch-up, under a word budget |
| No query path | `memory-query.py <topic-or-path>` and a `memory` skill: ADRs, notes, design docs, `git log -- <path>` |
| Claude, Gemini, Codex adapters | Claude Code only |
| Two ADR formats | One format; parser and INDEX fixed; dangling sources removed |
| `pre-commit` guard for unpublishable shards | Removed. Nothing local-only is generated any more. Generated `pre-commit` only delegates to `scripts/shared-repo-memory/project-pre-commit.sh`. |
| No evals | `evals/check_memory.py` (structural, runs in pre-commit) and `evals/run_eval.py` (fresh-session Q&A, with vs. without memory) |

## Layout

```
<repo>/.agents/memory/
├── adr/
│   ├── INDEX.md
│   └── ADR-NNNN-<slug>.md
├── notes/
│   └── YYYY-MM-DD.md          # decision notes, append-only, committed
├── config.json                # optional: decision_surfaces globs, context budget
└── local/                     # gitignored
    ├── catchup.md
    └── state.json             # last-seen sha for catch-up

~/.agent/shared-repo-memory/    # installed scripts
~/.agent/skills/{memory,memory-note,adr-promoter,memory-bootstrap,news}
~/.claude/skills/<skill> -> ~/.agent/skills/<skill>
```

## Note format

One file per day, entries appended, never rewritten:

```markdown
## 2026-09-05T14:02Z · davidthomas · feat/v0.5-decision-memory

**Decision:** Capture decisions at note and commit time, never per turn.
**Why:** Per-turn capture discarded intent and cost an LLM session per turn to recover it.
**Alternatives:** Keep per-turn capture but include the transcript (privacy risk at capture time).
**Scope:** scripts/shared-repo-memory/
```

A `candidate` entry written by the commit hook adds `**Commit:** <sha>` and `**Candidate:** true`.

## ADR format

```markdown
---
id: "ADR-0019"
title: "..."
status: "accepted"
date: "2026-09-05"
tags: "scripts,docs"
must_read: true
supersedes: ""
superseded_by: ""
---

# ADR-0019: <title>

## Context
## Decision
## Alternatives
## Consequences
## Sources
```

`Sources` lists note entries, commits, or docs. Sources are links only when the target is tracked in Git.

## Session-start context

Ordered, bounded by `context_budget_words` (default 2,500):

1. ADR INDEX (compact table)
2. `Decision` section of every `must_read: true` ADR, newest first
3. Notes from the last 14 days, newest first
4. `local/catchup.md` when present

When the budget is exceeded, later items are dropped and a one-line marker says what was omitted.

## Evals

`evals/questions.yaml` holds repo questions with `must_mention` terms. `run_eval.py` runs each question through `claude -p` with tools disabled in two conditions, *no memory* and *memory context prepended*, and reports coverage per condition. A run that shows no lift is a failing result, not a shrug.

`check_memory.py` verifies: every INDEX row has a file and vice versa, every link resolves, every ADR has the required sections, the injected context fits the budget. It runs from `project-pre-commit.sh`.
